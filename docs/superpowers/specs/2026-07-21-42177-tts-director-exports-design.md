# 42177 赛事解说 TTS 导演版设计

日期：2026-07-21

## 目标

在不改变 42177 回放事实、事件顺序、30 段时间轴和最终结果的前提下，改良 2 倍速解说正文，使其更像职业游戏主解说的现场口播，并从同一份正文派生通用 SSML 1.1 与自然语言导演提示两种配音输入格式。

## 现状与问题

现有 UI 对应版与纯配音版事实完整，时间轴从 `00:00` 连续到 `06:18`，但 1807 个口播单位的平均密度达到 4.78，30 段中有 16 段达到或超过 5.0。多数段落采用相近的句长、解释比例和情绪强度，配音工具容易使用稳定的新闻播报腔，缺少蓄势、爆发、落锤和复位。

## 采用方案

采用“单一正文主源、多格式派生”结构：

1. 新 UI 主稿保存改良后的唯一权威正文。
2. 新纯配音稿从 UI 主稿的每个 `**解说：**` 段落机械提取，不独立改写。
3. SSML 文件从同一正文派生，只增加通用语速、音高、音量、重音和停顿标签。
4. 自然语言导演稿从同一正文派生，每段给出可复制到风格提示栏的导演说明与对应台词。

这种结构能让 UI、纯配音、SSML 和导演稿共享同一组事实与措辞，避免多份文件分别修改后产生漂移。

## 正文改良规则

- 保留原来的 30 段、时间范围、画面说明和回放锚点。
- 不增加回放未证明的动作、心理、策略或结果。
- 总文字量压缩约 8%–12%，目标平均密度为 4.30–4.45 口播单位/秒。
- 行动发生时使用短句和主动动词；结果先落地，分析移到下一处低密度空档。
- 潼关设卡与三轮削弱形成第一高潮；朱雀门等待形成紧张低谷；二次设卡、验核和送达形成最高峰。
- 清理机械排比、连续同句式、解释过满、模板化转折和过度整齐的段落节奏。
- 保留正式队名、项目术语、比分、资源数值和最终胜者。
- 数字密集的结算段放慢并拆句，避免全段持续高喊。

## SSML 规则

根节点使用通用 SSML 1.1：

```xml
<speak version="1.1" xmlns="http://www.w3.org/2001/10/synthesis" xml:lang="zh-CN">
```

仅使用标准标签：

- `<p>`、`<s>`：组织段落和句子；
- `<prosody>`：设置 `rate`、`pitch`、`volume`；
- `<emphasis>`：强调队名、关键动作、比分和结果；
- `<break>`：插入毫秒级停顿。

不使用任何厂商专属 emotion、style、role 或 effect 标签。语速范围以 `92%–114%` 为主；高强度语速只用于短动作链。音高变化控制在 `-1st` 到 `+2st`，音量变化控制在 `soft`、`medium`、`loud` 这些标准值内。

## 自然语言导演稿规则

每段包含：

- 时间范围和场景名称；
- 情绪状态与强度；
- 建议语速；
- 需要压重的词；
- 句内、结果后和转场停顿；
- 句尾处理；
- 与 UI 主稿完全一致的台词。

导演提示与台词分栏呈现，避免配音工具把提示文字一并朗读。文档开头说明：提示内容放入风格或导演指令栏，台词只放入正文输入栏。

## 同步与校验

完成后执行以下检查：

1. 原件与备份 SHA-256 完全一致。
2. 新 UI 时间码连续，首段从 `00:00` 开始，末段在 `06:18` 结束。
3. UI 主稿与纯配音稿在空白归一化后逐字一致。
4. SSML 可被 XML 解析器正常加载。
5. 去除 SSML 标签后的口播正文与纯配音稿逐字一致。
6. 导演稿中的台词与纯配音稿逐字一致。
7. 自动审计满足 30 段、单段不超过 5.5、平均密度不超过 4.45。
8. 人工复核队名、数值、事件顺序、术语、比分和胜者。
9. 去 AI 腔检查不出现明显的模板式二元对立、助手式引导语和连续整齐排比。

## 异常处理

- 若某段压缩后丢失事实或因果关系，恢复必要信息，优先保证事实完整。
- 若 SSML 标签导致正文比对不一致，以 UI 主稿为准重新派生，不在 SSML 文件中单独改词。
- 若导演提示要求的停顿使台词无法落在原时间段内，先删减低优先级分析，不改变时间码或移动事件。
- 若通用 XML 解析通过但目标工具不支持某一标准标签，保留当前通用版本，另行制作工具适配版，不污染主稿。
